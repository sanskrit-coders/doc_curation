Manage Vedic mantra corpora across `~/gitland/vishvAsa/vedAH*` (`vedAH_Rk`, `vedAH_yajuH`, `vedAH`, `vedAH_sAma`) and host inclusions (venv: `~/gitland/python_venv`).

## Cross-śākhā Vedic reuse & deduplication

For the general two-part static layout (`vishvAsa-prastutiH/` + `sarvASh_TIkAH/`), pāṭha normalization, exact-vs-variant sharing rules, `js_include` `title` attributes, and `सर्वा अवतारिकाः` / `सर्वाष् टीकाः` wrapping, see the `commentary_translation` skill. Vedic-specific pipelines and rules:

- **Pipelines & corpus registry:** Consolidate parallel mantras across Vedic śākhās (`Śākala`/`AV`/`VS-M`/`VS-K`/`TS`/`TB`/`TK`, and `KS`/`MS`) via `doc_curation_projects.veda.dedup` (`doc_curation_projects/veda/dedup/cross_veda_targets.toml`), `doc_curation_projects.veda.yajuH.vaajasaneyi.dedup`, and `doc_curation_projects.veda.yajuH.ks_ms`.
- **US accents & comparison significance:** Preserve internal pluta digits (`२`/`३`), `ड`/`ळ` and nasal variants, and US accents (`᳓`/`᳙`) as significant when comparing mantras (`normalize_phonetic` / `is_no_patha_bheda`). All shared `vishvAsa-prastutiH/` and combined `yajuH/sarva-prastutiH/` files must use **US accents only** (see the `accenting` skill).
- **Combined non-Ṛk `yajuH/sarva-prastutiH/` vs. `Rk/`:** For shared strict non-Ṛk blocks (`>= 2` callers) without a separate `sarvASh_TIkAH/` split, use a combined `{yajuH,brAhmaNam}/sarva-prastutiH/{ch:02d}/{k:02d}_{storage_name}.md` (`includetitle="false"`). Never share combined `sarva-prastutiH/` on minor pāṭha variants — keep `विश्वास-प्रस्तुतिः` separate/local in each host śākhā and share only `sarvASh_TIkAH/` (`title="सर्वाष् टीकाः"`).
- **No single-caller Vedic `static/` files & unit-type suffixes:** Do not keep `<= 1`-caller files under non-sūtra Vedic `static/` trees (`vishvAsa-prastutiH/`, `sarvASh_TIkAH/`, `{yajuH,brAhmaNam}/sarva-prastutiH/`). Keep variant or single-caller `विश्वास-प्रस्तुतिः` blocks inline in the host until a 2nd exact caller requires sharing (`doc_curation_projects.veda.dedup.static_fixer.inline_single_caller_veda_static` inlines `1`-caller and prunes `0`-caller files across `vishvAsa/*/{content,static}`). Any inlined or variant-retained `विश्वास-प्रस्तुतिः` `<summary>` carries a `- ऋक्`, `- यजुः`, or `- ब्राह्मणम्` suffix immediately before any trailing `(यन्त्र-स्वरः)` or `(N/P व्यत्यस्त-स्वराः)` tag (`block_parser.format_vp_summary_with_kind`, e.g. `विश्वास-प्रस्तुतिः - ब्राह्मणम् (1/13 व्यत्यस्त-स्वराः)`).
- **Śākhā labels in shared `sarvASh_TIkAH/`:** Disambiguate with `<summary>मूलम् - <Śākhā></summary>` (`मूलम् - शाकलम्`, `मूलम् - शौनकम्`, `मूलम् - माध्यन्दिनम्`, `मूलम् - काण्वम्`, `मूलम् - तैत्तिरीयम्`), `<summary>पदपाठः - <Śākhā></summary>` (`पदपाठः - काण्वः`, `पदपाठः - दयानन्दादि`, `पदपाठः - तैत्तिरीयः`), and śākhā-qualified commentator titles (`<summary>सायण-टीका (काण्वी)</summary>`).
- **Host-local `सर्वा अवतारिकाः` & Ṛk hemistich granularity:** Never place `*विनियोगः` blocks inside Yajurveda `sarvASh_TIkAH/` files (`commentary_translation` skill); keep `<details><summary>सर्वा अवतारिकाः</summary>` (`*विनियोगः`, `*अवतारिका`) per śākhā in the host file above `विश्वास-प्रस्तुतिः`/`js_include`. Merge split-hemistich Ṛk halves in a host when no liturgical viniyoga divides them (relocating misattached whole-stanza/next-clause viniyogas); if genuine split viniyoga separates the halves, split the shared `static` files and update all host includes across repos.
- **Corpus provenance:** After editing shared hosts, refresh transitive `js_include` prefills across `vishvAsa` repos (see the `website` skill) and verify `VedicCorpusCounter` (`doc_curation.sanskrit.accent.provenance`, see the `accenting` skill) excludes foreign `मूलम् - <OtherŚākhā>` blocks when ingesting shared hosts.

## Accents, validation & sibling skills

- **Vedic accents (`accenting` skill):**
  - Match notation to the block: `विश्वास-प्रस्तुतिः` always uses **US accents (`᳓`/`᳙`)** (`accent.to_US_accents` / `to_us_accents_markdown(..., preserve_existing_us=True)`), whereas `मूलम्` retains the source's own notation (classically dependent `॒`/`॑`).
  - Suggest svara corrections in accented text as `[[OLD|NEW]]` rather than silently overwriting (except fake accents, de-novo `(यन्त्र-स्वरः)`, and splitting fixes), and document mechanical/de-novo padapāṭha provenance in `<details><summary>पद-पाठः (यान्त्रिकः...)</summary>` (citing valid corpora `*TS*, *RV*, *TB*, *TK*, *AV*, *SB-M*, *SB-K*, *VS-M*, *VS-K*, *KS*, *MS*`, never `*TA*` or `*EK*`; see `grammar` skill §6 for padasvara/prakṛti-svara lookups).
  - Never embed `sarvASh_TIkAH/` or `पद-पाठः (यान्त्रिकः)` inside `vishvAsa-prastutiH/` files, and run `doc_curation.sanskrit.accent.validator`, `reconciler`, and `auditor` (`~/gitland/python_venv/bin/python -m doc_curation.sanskrit.accent.auditor <dirs...> --with-reconciler`) after accent or layout edits.
- **Commentaries, translations & wrappers (`commentary_translation` skill):** Align commentaries/translations (`*विनियोगः`, `*- अवतारिका`, `विश्वास-प्रस्तुतिः`, translations, `मूलम्`, `*-टीका`), wrap non-`विश्वास-प्रस्तुतिः` blocks into `सर्वाष् टीकाः` (by default, especially when multiple) / `सर्वा अवतारिकाः` and enforce `title="विश्वास-प्रस्तुतिः"` (**exception:** if included inside another `vishvAsa-prastutiH` file, let there be no title — use `includetitle="false"` and omit `title`) / `title="सर्वाष् टीकाः"` on `js_include`s per the `commentary_translation` skill (never wrapping single-layer `static/.../sarvASh_TIkAH/` or `static/.../vishvAsa-prastutiH/` files), and never place `*विनियोगः` blocks inside Yajurveda `sarvASh_TIkAH/` files.
- **Markdown structure & bulk transforms (`md-processing` skill):** Treat `js_include` divs as atomic boundaries, preserve `<details>` invariants, and run `MdFile` bulk transforms.
- **Sense-unit block creation/splitting (`text_to_blocks` skill):** Generate or split paired `विश्वास-प्रस्तुतिः` / `मूलम्` clusters while keeping `मूलम्` verbatim and converting `विश्वास-प्रस्तुतिः` to US accents.
- **Includes & prefills (`website` skill):** Resolve `js_include` targets via `include.resolve_include_file_path` and propagate edits across transitive hosts via `include.surgical_prefill_transitive`.
